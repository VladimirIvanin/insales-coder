# Форма обратной связи

Для штатной формы нужны `commonjs_v2`, а для собственного jQuery — `jquery`. Разметка, имена полей и капча описаны в [forms.md](../commonjs-widget/forms.md). Используй один путь отправки компонента: собственный fetch/submit-handler поверх него может дать дубли. Капча включается только по настройке магазина и подтверждённому типу.

Поля имени/email/сообщения и согласия получают нужные правила обязательности; необязательный телефон не должен блокировать пустое значение. Label либо оборачивает input, либо связан с уникальным id; соседний текст без связи не является label. Экранируй подписи также в placeholder/href/value. Для JSON-атрибутов сериализуй значения и экранируй итоговый объект, как в [правилах разметки](../commonjs-widget/markup.md).

## Состояния common.js

Штатный success-блок `[data-feedback-form-success]` получает класс `is-show`. Компонент не обязан добавлять `is-sended` форме или родителю. Минимальный CSS:

```scss
[data-feedback-form-success] {
  display: none;
}

[data-feedback-form-success].is-show {
  display: block;
}
```

Если собственный callback добавляет класс обёртке, CSS должен обращаться к этой же обёртке. Проверь видимое сообщение после ответа сервера, а не только наличие нового класса.

Событие успеха передаёт `{form}` с jQuery-формой. Фильтруй по точному DOM-узлу своей формы. У `error-feedback:insales:ui_feedback` payload может быть объектом отказа AJAX, без `form`; не предполагай единый формат успеха и ошибки.

Для локального статуса ошибки можно запоминать собственную отправку по `before-send-feedback:insales:ui_feedback` (`{form}`), принимать ошибку только при активной отправке своей формы, а по `after-send-feedback:insales:ui_feedback` освобождать это состояние. Эти события относятся к циклу компонента; не запускай из них ещё один запрос. При необходимости параллельных запросов отдельно подтверди корреляцию ответа: один глобальный payload ошибки не даёт ID формы. Не показывай чужую ошибку всем экземплярам.

## Жизненный цикл

Если хватает встроенных success/validation состояний, собственный snippet.js не нужен. Если добавляешь EventBus-статусы, callback объявляется в области, где доступен cleanup, и отписывается той же ссылкой. Имя `function onSuccess` внутри аргумента subscribe не создаёт binding onSuccess в соседней cleanup-функции.

Перед новым mount вызови disposer предыдущего. Обычный DOM/jQuery remove не гарантирует событие `remove`; механизм освобождения внешних подписок выбирается по [runtime](runtime.md). Локальный пустой массив disposers при каждом запуске не очищает предыдущий mount.

Не заменяй внутренности формы сохранённой строкой HTML при любом глобальном editor-event: так теряется незавершённый ввод соседних экземпляров и состояние компонента. При реальной замене работай с новым узлом формы и её подтверждённой инициализацией, не придумывай автоматическую переинициализацию из одного наличия data-атрибутов.

Проверь пустые/неверные поля без POST, исправление, один запрос, видимый success и отказ сервера, соседнюю форму, повторный mount, удаление/перерисовку, кавычки в редактируемых подписях и мобильную клавиатуру. Недоступная капча/доставка оставляет успешную отправку непроверенной; статический fixture с событием не заменяет серверный путь.
