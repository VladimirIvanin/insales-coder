# Обычная шапка: данные и состояния

Читай при создании или переносе шапки. Начни с выбранных пользователем функций и композиции: зоны логотипа, поиска, действий и каталога, поведение на узком экране. Магазин, MCP и браузер полезны для дополнительной проверки, но не нужны для подготовки и проверки исходников. Точное повторение стиля нужно, когда оно заказано; ниже один возможный интерфейс, а не стандарт оформления.

`info.json`: для штатной категории шапок используй `widget_category_handle: "headers"`, для размещения — `widget_list_kinds: ["header"]`; это разные справочники. Наличие категории в целевом каталоге проверяется отдельно.

## Основной пример: шапка с панелью каталога

[Полный пакет](examples/header/info.json): [snippet.liquid](examples/header/snippet.liquid), [snippet.js](examples/header/snippet.js), [snippet.scss](examples/header/snippet.scss), [форма](examples/header/settings_form.json), [defaults](examples/header/settings_data.json), [сообщения](examples/header/messages.json). Его можно копировать в отдельную папку виджета, выбрав свой handle. Превью галереи добавляются при подготовке публикации.

Основной ряд: логотип → кнопка каталога → одна форма поиска → действия. Каталог закрыт при загрузке и открывается отдельной панелью: на широкой ширине — сетка категорий и дочерних ссылок, на узкой — модальная панель с раскрытием веток по их названиям. Подкатегории не раздвигают основную шапку постоянными колонками.

Дополнительное меню выбирается полем `menu-handle` из `linklists`. Пустой default не предполагает существования конкретного handle. На desktop локальный ResizeObserver переносит не поместившиеся ссылки в нативный details «Ещё», на mobile те же ссылки доступны в панели. Пересчёт возвращает ссылки в исходном порядке и не использует глобальные подписки библиотеки. Для шапки без такого меню убери соответствующие разметку и initializer вместе. [InsalesCutList](../libraries/navigation-filters.md) — альтернативный вариант, когда проверены teardown и независимость экземпляров конкретной сборки. Каталог категорий и горизонтальное меню — разные источники данных и разные компоненты.

В примере панель «Ещё» абсолютно позиционирована внутри меню. `overflow: hidden` или `clip` на меню/его предках обрежет ссылки ниже строки; увеличение z-index это не исправляет. Сохраняй видимое переполнение либо выноси панель в отдельный слой. Проверяй доступность ссылок после открытия, а не только появление кнопки «Ещё».

Для адаптации JS сохраняй `const`/`let` из примера. Inline-подключение и jQuery не требуют переписывать объявления в `var`; совместимость с более старым синтаксисом выбирается только по требованиям целевой среды.

Пакет использует `jquery`, `commonjs_v2`, `my-layout`, `body-scroll-lock`. `my-layout` нужен для `.layout__content`; если выбираешь собственную раскладку без его классов, не подключай его автоматически. Для каждой дополнительной библиотеки сохраняй её cleanup по [lifecycle](runtime.md).

`logo` — поле `file`, `logo-alt` — объявленное текстовое поле; без файла работает `{% default_logo %}`. Растровый URL выводится через `image_url`, SVG — исходным URL. Проверка `.svg` в примере подходит для URL с расширением; для URL без него используй известный формат файла. Пример не подставляет путь к локальному файлу вместо значения AccountFile. Если добавляешь свои обращения `widget_settings.*`, объявляй соответствующие поля/defaults либо используй документированную настройку платформы.

Изображение и fallback SVG ограничены шириной своей ячейки и высотой 48 px: большой исходник не должен перекрывать каталог или поиск. Имя ссылки логотипа задаётся отдельно. У кнопки каталога есть `aria-label` из `widget_messages.catalog`; если адаптация скрывает видимый текст на узком экране, имя действия сохраняется. Для других кнопок с иконкой обеспечь такое же независимое имя.

Подписи в форме используют `messages`, в Liquid — `widget_messages`. Строковые defaults в пакете не требуют словаря локалей; объекты переводов тоже поддерживаются там, где это предусмотрено платформой. Вариант defaults проверяй сохранением и повторным открытием редактора.

Данные каталога — три уровня `collections.root_category.subcollections`; третий уровень остаётся ссылкой на категорию. Не подменяй их статическими названиями. При добавлении кеша учитывай зависимости каталога, выбранного меню и настроек по [контракту кеша](../liquid-widget-cache-keys/reference.md).

`data-navigation` обозначает корень, `data-navigation-item` — пункт, `data-navigation-link="URL"` — ссылку, `data-navigation-submenu` — вложенный список. Проверенный common.js добавляет `.is-current` ссылке и предкам по точному совпадению `location.pathname` со значением `data-navigation-link`, затем ставит `data-navigation-inited`. Эти атрибуты **не открывают подменю**. В примере собственная локальная проверка pathname также ставит `aria-current="page"` и работает при повторном запуске JS; dropdown-поведения common.js не предполагается.

## Поиск и действия

Поиск остаётся видимым в обеих раскладках: одна форма, `name="q"`, скрытый `lang`, `data-search-field` и `data-search-result` в той же форме. Отправка `/search` работает и без живой выдачи. `commonjs_v2` обслуживает AjaxSearch; не добавляй второй обработчик запросов и не меняй глобальный `AjaxSearch.setConfig` ради одного экземпляра.

Штатная выдача использует `.ajax-search-results`, `.ajax-search-item`, `.ajax-search-link`, подсветку `.ajax_search-marked`; класс `.is-show` получает **форма** при наличии результатов. SCSS должен оформить контейнер, ограничить высоту, разрешить scroll и обеспечить доступ к ссылкам при узкой ширине. При пустом/слишком коротком запросе стандартный шаблон пуст, `.is-show` снимается: это не отдельное сообщение «Ничего не найдено». Если дизайн требует loading/empty/error и полноценный combobox с управлением стрелками, реализуй эти состояния отдельно по [API поиска](../commonjs-widget/js-api.md), не объявляй их автоматическими свойствами data-атрибутов.

common.js обновляет `data-cart-positions-count`, `data-ui-favorites-counter`, `data-compare-counter` и классы пустоты `.cart-empty`, `.favorites-empty`, `.compare-empty`. Скрывай пустой **бейдж**, оставляя ссылку доступной. Начальные пустые классы предотвращают мелькание нулей. Для корзины `cart-empty` обновляется **на самом `[data-cart-positions-count]`**, не на родительской ссылке. Начальный класс и правило скрытия привязывай к этому же бейджу:

```liquid
<a href="{{ cart_url }}">
  {{ widget_messages.cart | escape }}
  <span class="header-cart-count cart-empty" data-cart-positions-count>0</span>
</a>
```

```scss
.header-cart-count.cart-empty { display: none; }
```

Если навсегда поставить `cart-empty` на ссылку и скрывать её дочерний счётчик по этому классу, бейдж останется невидимым после наполнения корзины. Проверь оба перехода `0 → 1 → 0`, включая computed visibility, а не только текст узла.

Доступность функции решает Liquid: `account.show_cart?`, `settings.favorite_enabled == true`, `settings.compare_enabled == null or settings.compare_enabled`. Настройки скрытия конкретного виджета добавляй, если они нужны заданию; не создавай второе клиентское хранилище счётчиков. После изменений корзины данные поступают из штатных событий common.js; обычному счётчику не нужен собственный polling.

## Мобильная панель и жизненный цикл

На desktop нативный `<dialog>.show()` открывает немодальную панель под шапкой. Она закрывается повторной кнопкой, действием внутри панели, кликом снаружи и Escape. На mobile `showModal()` обеспечивает модальность/фокус, а `bodyScrollLock` блокирует прокрутку фона и оставляет прокручиваемый panel. Поддержку dialog сопоставь с целевыми браузерами; альтернативный вариант — [MicroModal](../libraries/overlays.md) с теми же состояниями.

Смена breakpoint закрывает панель и обновляет режим раскрытия категорий и меню. Если на desktop скрываешь `summary` категорий, открой соответствующие `details` через `open`: закрытый нативный `details` прячет дочерние ссылки независимо от оформления контейнера. При возврате на mobile восстанови выбранное начальное состояние веток, как в `updateBranches()` примера. При обычном закрытии возвращается предыдущий фокус; при удалении он не перемещается на отсоединённый узел. Диалог получает отдельный ID каждого экземпляра. Не пиши `body.style.overflow = 'auto'`: это может разблокировать чужую панель.

JS инициализирует каждый элемент `$widget` отдельно, хранит cleanup на его корне и вызывает его перед повторным запуском. Наблюдатель освобождает обработчики и lock при удалении корня или замене его содержимого. Сохранённый корень ещё не означает, что диалог жив: проверяй принадлежность захваченных `dialog`, `panel` и `toggle` этому экземпляру. Удаление открытого диалога при оставшейся шапке также должно освобождать lock. Вставка новой разметки требует запуска initializer платформой или адаптера по [общему lifecycle](runtime.md); сам наблюдатель пример заново не создаёт. При подключении общего runtime перенеси этот cleanup в его disposer, чтобы не держать два наблюдателя. В common.js обработчик виджетов принимает `update_widget:insales:widgets` и обновляет Cart/Favorites/Compare/меню после перерисовки; это событие не является подтверждённым событием удаления. Общие API common.js не уничтожай из cleanup отдельной шапки.

## Учебный минимум

[Минимальный Liquid](examples/header-minimal/snippet.liquid), [JS](examples/header-minimal/snippet.js), [SCSS](examples/header-minimal/snippet.scss) показывают простой каталог через details с горизонтальной прокруткой на desktop. ## Проверка выбранных функций

Офлайн используй доступные инструменты для проверки синтаксиса JS, компиляции SCSS и Liquid на fixtures каталога и flags. Если есть DOM harness, проверь открытие/закрытие, cleanup и два экземпляра. Непроведённые проверки перечисли с причиной. Разделяй заглушки и фактический runtime: fixtures не подтверждают серверный поиск, корзину или редактор. Сохрани команды, результат и ограничения. Этого достаточно для исходников без подключённого магазина.

При доступной витрине проверь 390/1024/1440 px: закрытый каталог при загрузке, desktop-панель и мобильную навигацию, переполнение выбранного меню и доступ к его ссылкам на mobile, длинные категории и подписи действий, широкий/высокий логотип и fallback SVG, доступные имена кнопок при скрытых подписях, все выбранные уровни, горизонтальный overflow, desktop mouse/touch, поиск с результатами/без результатов, пустые/непустые/выключенные controls. Для панели проверь Escape, Tab/Shift+Tab, возврат фокуса, scroll, resize при открытии; для lifecycle — rerender/settings, удаление открытой панели и независимость двух экземпляров. Оцени читаемость и доступность действий; сравнение пикселей нужно по заданию. Sticky, мегаменю с фото, языки, телефон, видео/slider и пересчёт visualViewport добавляй только при соответствующей задаче.

Контракты поиска, счётчиков и меню описаны в [разметке common.js](../commonjs-widget/markup.md) и [JS API](../commonjs-widget/js-api.md). Пример использует эти справочники и включённые в скилл файлы; отдельная копия исходников платформы ему не требуется.
