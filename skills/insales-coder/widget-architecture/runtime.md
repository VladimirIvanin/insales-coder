# Состояния виджета и время жизни обработчиков

Выбирай поведение до подключения библиотек и написания cleanup:

| Что делает виджет | Достаточный механизм |
|---|---|
| Выводит текст, изображения и обычные ссылки | Liquid/CSS, без `snippet.js`; [полный статический пакет](collection-links.md) |
| Обрабатывает клики внутри своего экземпляра | Обработчик на корне с защитой от повторной инициализации |
| Создаёт компонент, таймер, глобальную подписку или блокировку прокрутки | Инициализация и освобождение каждого созданного ресурса |

Пустой cleanup, который только удаляет собственное свойство, не добавляет поведения. Нативный `loading="lazy"` подходит обычным изображениям без клиентской подмены; отдельный lazyload нужен, когда его возможности используются.

## Локальные события

Инициализируй каждый элемент `$widget` отдельно. Для переключателя внутри корня достаточно именованной делегации; повторный запуск снимает только собственный обработчик:

```js
$widget.each(function (_, root) {
  const $root = $(root)
  const selector = '[data-disclosure-toggle]'
  $root.off('click.widgetDisclosure', selector)
  $root.on('click.widgetDisclosure', selector, function () {
    const panel = root.querySelector('[data-disclosure-panel]')
    if (!panel) return
    const expanded = this.getAttribute('aria-expanded') === 'true'
    this.setAttribute('aria-expanded', String(!expanded))
    panel.hidden = expanded
  })
})
```

Здесь предполагается одна кнопка и одна панель на экземпляр. Для нескольких пар сопоставь кнопку с её панелью внутри `root`. Нужен `jquery` в `libraries`. Не используй общий `.off('click')`: он снимает чужие обработчики. При штатном удалении корня средствами jQuery снимаются и его локальные обработчики; глобальные подписки требуют отдельной очистки.

`$widget` предоставляется платформой; `$root` из примера — локальная переменная `const $root = $(root)`, её нужно объявить в каждом callback. При адаптации примера сохраняй эту область видимости и исполняй initializer: синтаксическая проверка не обнаруживает обращение к необъявленной переменной.

Для нового JS используй `const`, а при переназначении — `let`. Совместимость существующего кода может потребовать другого решения; сам inline-способ подключения не требует ES5. Обёртка платформы и область видимости описаны в [архитектуре](reference.md#snippetjs).

## Срок жизни состояния

Определи, что должно сохраняться при перерисовке экземпляра, переходе на другую страницу, перезагрузке и открытии новой вкладки. Эти границы следуют из задачи, а не из выбранного хранилища: `sessionStorage`, например, переживает перезагрузку. Не усложняй реализацию сохранением, которого задача не требует. Если контракт прототипа опирается на SPA-навигацию и меняется при переносе на серверные страницы, обозначь различие вместо неявной подмены поведения.

Состояние и ключи хранения должны различать независимые экземпляры. Повторный initializer не равен новой пользовательской сессии и не должен сам по себе терять ещё нужное состояние. Проверяй отдельно действие, повторную инициализацию и те переходы, на которых состояние должно сохраняться или сбрасываться. Подписи интерфейса должны соответствовать фактическому поведению.

## Внешние ресурсы и teardown

Храни ссылки на созданные callbacks. Перед повторной инициализацией и до удаления экземпляра сними подписки на document/window/EventBus, останови свои таймеры, вызови `destroy()` компонента и освободи принадлежащую ему блокировку прокрутки. Проверка `root.isConnected` внутри callback не снимает глобальную подписку. Временная невидимость (`:visible`, `display:none`, закрытая панель) не означает удаление: отписанный при скрытии экземпляр перестанет получать события после показа. Проверяй принадлежность захваченных узлов корню, а не только видимость. Если cleanup вызывается после jQuery `.remove()`, данные `$(root).data()` уже могут быть очищены. Сохраняй disposer и ссылки на ресурсы в замыкании или другом хранилище, которое не исчезает раньше отписки; не получай их только из очищаемого jQuery-кеша.

Не добавляй `MutationObserver` для обнаружения удаления корня или замены его содержимого — ни на витрине, ни в редакторе. Не заменяй его опросом DOM по таймеру. Владелец, который удаляет или заменяет компонент, должен явно вызвать сохранённый cleanup **до изменения DOM**, а после вставки новой разметки — запустить initializer. Повторный initializer сначала вызывает прежний cleanup. Само удаление DOM не вызывает disposer: если владелец не предоставляет teardown, автоматическая очистка при произвольном удалении не обеспечена. Не выдумывай событие уничтожения платформы. Централизованный вызов disposer можно подключить после появления подтверждённого системного lifecycle.

У common.js `EventBus.subscribe(event, callback)` не возвращает функцию отписки. Используй `EventBus.unsubscribe(event, тотЖеCallback)`. Шина запоминает последнее событие и может вызвать callback прямо при подписке: подготовь состояние до `subscribe`, фильтруй источник события и не запускай из такого callback повторную покупку или другой запрос с побочным эффектом.

[Пример подписки на вариант](examples/runtime/snippet.js) обновляет дополнительную подпись конкретной формы. Нужны `jquery`, `commonjs_v2` и `<span data-variant-preview></span>` в форме. Поля `data.action.product[0]` и `data.title` приходят из common.js. Сохранённый `root.__variantPreviewCleanup` снимает глобальную подписку; владелец вызывает его перед удалением или заменой формы. Штатные цена, количество и покупка не меняются.

У собственных fetch/Deferred-запросов учитывай удаление экземпляра и устаревший ответ; способ отмены зависит от используемого API.

## Выбор варианта и количество

Штатная форма, `data-product-variants`, `data-quantity` и `data-item-add` описаны в [разметке common.js](../commonjs-widget/markup.md). Не добавляй вторую независимую реализацию корзины поверх этих атрибутов. Актуальные ID, цены, наличие и фото бери из каталога.

`change_variant:insales:product` сообщает о смене выбранного ID; `update_variant:insales:product` используется также при последующих обновлениях состояния. В обоих случаях сначала сопоставь `data.action.product[0]` с формой своего экземпляра. Последнее полученное событие другого товара не является готовностью текущей формы. Общие `before`/`always` не следует объявлять индикатором окончания выбора варианта без проверки их payload и порядка в используемой сборке.

При собственной загрузке данных отделяй состояния «обновляется», «готово» и «ошибка». Пока обработчик завершает выбор варианта, пользователь не должен незаметно терять уже введённое количество. Не сбрасывай поле на `1` при каждом событии и не лечи гонку фиксированным timeout. Если нужна блокировка действий на время запроса, связывай её с подтверждённым началом/завершением именно этого запроса и восстанавливай прежнее disabled-состояние; наличие товара по-прежнему определяет common.js.

Когда доступна витрина, сравни два пути на одном товаре: сменить вариант → сразу ввести количество и добавить; затем повторить после стабилизации данных. В обоих случаях проверь фактические variant_id, количество и сумму в корзине. Если результат расходится, сравни со штатной карточкой на том же товаре, прежде чем приписывать причину виджету или библиотеке. Офлайн проверь ветви кода и запиши, что этот сценарий ещё не выполнен.

## Значение файловой настройки

Для поля `{"name":"image","type":"file"}` значение выбранного файла в данных экземпляра имеет вид:

```json
{
  "image": { "_type": "AccountFile", "id": "123" }
}
```

`123` здесь условный ID: используй ID действительно загруженного файла этого магазина. Это значение не равно строке URL и не равно одному числу. На витрине `widget_settings.image` разрешается платформой в URL:

```liquid
{% if widget_settings.image %}
  <img src="{{ widget_settings.image | image_url: 1000 }}" alt="{{ widget_settings.image-alt | escape }}">
{% endif %}
```

Без доступа к магазину оставь поле `null`, приложи локальный файл и соответствие «файл → настройка». Привязка ID выполняется после загрузки через доступный редактор/API; MCP — один из способов, не обязательная зависимость. После загрузки проверь сохранённый тип/ID и изображение; не подменяй незаполненную настройку постоянным URL сайта-референса. `image_url` применяй к растровым изображениям; для SVG логотипа обычно нужен исходный URL.

## Минимальная проверка по выбранным функциям

| Офлайн | При доступной витрине/редакторе |
|---|---|
| Два DOM-экземпляра реагируют только на свою форму | Два экземпляра независимо работают на странице |
| Повторный mount не удваивает действия; destroy снимает callbacks | Явный cleanup перед перерисовкой/удалением освобождает подписки, компонент и scroll lock, не затрагивая соседний экземпляр |
| Сохранённое событие и поздний ответ не мутируют другой/удалённый экземпляр | Быстрый следующий шаг после смены варианта не теряет количество |
| File-поле пусто или имеет корректную структуру; локальные assets приложены | Выбранный файл сохраняется и показывается после повторного открытия |

Проверяй только используемые механизмы. DOM-fixture не доказывает загрузку библиотек, поиск, цену или работу корзины на настоящей витрине. Отличия шрифта или форматирования исходников сами по себе не являются функциональным дефектом; при доступной теме проверяй прежде всего читаемость и доступность действий.

Методы и события описаны в [JS API](../commonjs-widget/js-api.md), файловые настройки — в [справочнике настроек](settings-reference.md). Для другой сборки сверяй доступный API с документацией этой версии; название записи каталога не гарантирует состав API.
