# Cookie-уведомление

Для баннера на всех страницах обычно нужны page_kinds `all`, размещение `outside`, существующая категория `modal_cookie` и непосредственная зависимость `js-cookie`. jQuery/my-layout объявляются только при использовании. Немодальное уведомление не блокирует прокрутку, не удерживает фокус и не получает aria-modal.

## Выбор и состояние

Сохраняй два явных значения, например `accepted` / `declined`, одним ключом с expires365 и path `/`. Проверяй конкретное значение, а не его истинность: сохранённый отказ также означает сделанный выбор. Чтение и запись могут бросить исключение; текущий клик всё равно закрывает уведомление. Хранилище определяет следующий показ, но не заменяет состояние текущего DOM.

Текст и подписи редактируемые. Если ссылка политики выделена отдельной настройкой, используй её в href с escape; не оставляй настройку неиспользуемой и не закрепляй URL внутри default HTML вместо неё. Один баннер не является реализацией загрузки/блокировки сторонних скриптов: описывай только фактически реализованное поведение.

## Инициализация и editor preview

Сначала подключи scoped обработчики кнопок и preview, затем примени сохранённый выбор к видимости. Ранний return при существующей cookie скрывает баннер, но может оставить его без кнопок при последующем открытии preview.

Раздели причины показа:

- обычный mount: показать, если выбор не сохранён;
- open-preview: показать независимо от cookie, не меняя её;
- close-preview: закрыть preview, не перечитывая «нет выбора» как команду снова открыть;
- выбор человека: попытаться сохранить значение и сразу скрыть все экземпляры этого уведомления.

Два экземпляра могут инициализироваться вместе или отдельно после перерисовки. Замыкание над одной переданной `$widget`-коллекцией не всегда содержит все живые экземпляры. Для синхронизации выбирай актуальные узлы того же типа по платформенному `widget`-селектору либо используй собственное явно названное событие с cleanup; не кликай чужие кнопки глобальным `.js-cookies-button`.

Если есть listener на document для close-preview, каждый mount снимает только свой callback; глобальный off с общим namespace может снять обработчик соседнего экземпляра. Сохранённый disposer и внешние ресурсы — в [runtime](runtime.md). Не оставляй невызываемую destroy-функцию как доказательство teardown.

Проверь принятие и отказ отдельно, reload после каждого, ошибки чтения/записи, два экземпляра и частичный mount, сохранённый выбор → open-preview → клик, close-preview при пустом хранилище, повторный init и удаление. На узком экране весь текст и обе кнопки доступны без блокировки остальной страницы.
