# Страница корзины

[Полный пакет](examples/cart-page/info.json): [snippet.liquid](examples/cart-page/snippet.liquid), [snippet.js](examples/cart-page/snippet.js), [snippet.scss](examples/cart-page/snippet.scss), [форма](examples/cart-page/settings_form.json), [defaults](examples/cart-page/settings_data.json), [сообщения](examples/cart-page/messages.json). Копируй папку, выбирай собственный handle и оформление. Нужны `jquery`, `commonjs_v2`, `my-layout`; `.layout__content` использует последний. MCP не требуется для подготовки пакета.

## Назначение

Это обычная страница `cart`, один экземпляр с одной штатной `data-cart-form` на странице. В ней показаны позиции, фото/fallback, количество, удаление, промокод, суммы и переход к оформлению. Список и цены впервые выводятся сервером из `cart`; покупки и изменения выполняет common.js. Структуру заказа, доставку, купон и скидки не вычисляй самостоятельно.

- Ссылка на товар строится из `item.product.url` и параметра `variant_id`; `item.url` является адресом строки корзины и для перехода к товару не подходит. Изображение берётся из `item.image.original_url` и передаётся в `image_url`.
- `data-item-id` и имя `cart[quantity][…]` используют `item.id`, который в этом контексте является variant ID. `cart_line_id` — другой идентификатор. Не заменяй один другим по названию.
- Для строк одного варианта с разными опциями сохраняются `data-item-accessories` и `data-item-accessory-value-id`. Клиентское сопоставление учитывает и вариант, и отсортированные ID опций.
- `data-cart-total-price` получает итог с учётом скидок (`total_price`), `data-cart-full-total-price` — сумму товаров до скидки заказа (`items_price`). Отображаемые значения обновляет common.js; `money` даёт начальный серверный вывод.
- Купон использует штатную кнопку и `data-cart-discounts-error`/`data-cart-discounts-ajax`. Флаг `data-reload-on-coupon="false"` оставляет обновление цен и ошибок на странице. Сообщения вставляет common.js; не дублируй запрос купона. Собственная кнопка удаления вызывает штатный `Cart.setCoupon` с пробелом: пустая строка/`false` в этой сборке не передаётся в запросе и не снимает уже применённый купон. Одинаковую ошибку, которую библиотека вставляет сразу в два контейнера, показываем только в отдельном блоке ошибок; общий fallback нужен, когда такого блока нет.

Свои callbacks только удаляют исчезнувшие строки после подтверждённого обновления и переключают пустое состояние. При ошибке удаления строка не исчезает заранее. Поле количества, в котором пользователь сейчас вводит значение, не переписывается собственным callback. Повторная инициализация снимает прежнюю собственную подписку. Перед удалением или заменой формы владелец явно вызывает `root.__cartPageCleanup` по [контракту cleanup](runtime.md#внешние-ресурсы-и-teardown); `always` не считается подтверждением успеха.

## Границы примера

Пакет не является динамическим drawer корзины. Если другой компонент добавил новую строку, которой нет в серверной разметке, вместо неполного списка показывается явная ссылка обновления. Она получает свежую серверную корзину без собственного HTML-рендера товарных данных и не запускает перезагрузку из сохранённого события EventBus. Пустая корзина также содержит скрытую штатную форму для инициализации common.js.

Не размещай две независимые `data-cart-form` на одной странице: некоторые штатные обработчики собирают поля сразу из всех таких форм. Повторный mount собственного JS поддерживается, но полная замена формы в редакторе требует проверки повторной инициализации common.js конкретной сборки. Сценарии мультискладов, shared cart, составных комплектов и динамически добавленных опций требуют отдельного расширения. Подарочная строка отображается без изменения количества и удаления.

## Проверка

Проверь пустую корзину, один/несколько товаров, отсутствие фото, одинаковый вариант с разными опциями, изменение количества, ограничение по остатку, удаление последней позиции, корректный и ошибочный купон. Суммы сравнивай с ответом корзины, а не с собственной суммой цен карточек. Кнопка оформления отправляет штатную форму с `_method=put` и полем `make_order`; без последнего часть конфигураций возвращает на страницу корзины вместо оформления. Заказ при проверке создавать не требуется.

На витрине проверь узкую/широкую раскладку и состояние после ответа сервера. DOM fixtures подтверждают переключение своих состояний и cleanup, но не покупку, серверные скидки или обработку сетевого сбоя библиотекой. Неисправный транспорт common.js не лечи вторым запросом или таймаутом в этом примере.
