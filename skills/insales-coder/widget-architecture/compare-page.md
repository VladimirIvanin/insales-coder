# Страница сравнения товаров

Используй для таблицы сравнения с удалением колонок и переключателем различий. Данные страницы — `products` и `properties`: заголовок строки `property.title`, handle — `property.handle`, значения ячейки — `product.properties[property.handle].characteristics`, подпись значения — `characteristic.title`. Это Liquid-контракт; клиентский JSON может иметь другую структуру.

Для нового gen4-пакета: страница `compare`, размещение `content`, категория `compare`. Штатные действия сравнения обслуживает `commonjs_v2`; собственному JS с jQuery нужны `jquery` и `commonjs_v2`. `my-layout` подключай при использовании его раскладки. Покупка не является обязательной частью сравнения.

## Полный пример

[Пакет сравнения](examples/compare-page/info.json): [snippet.liquid](examples/compare-page/snippet.liquid), [snippet.js](examples/compare-page/snippet.js), [snippet.scss](examples/compare-page/snippet.scss), [форма](examples/compare-page/settings_form.json), [defaults](examples/compare-page/settings_data.json), [сообщения](examples/compare-page/messages.json). Скопируй семь файлов и выбери собственный handle. Пример удаляет готовые колонки, пересчитывает различия и освобождает подписку при удалении/замене разметки; дозагрузка новых колонок в него не входит.

## Кеш таблицы

Состав сравнения относится к посетителю. По умолчанию не помещай всю такую таблицу в общий Liquid-кеш. `widget_basic_cache_key` и `account.products_basic_cache_key` описывают настройки/каталог, но не различают два списка сравнения. Изменение состава и порядка списка также меняет HTML, даже если каталог не обновлялся. Кеш допустим только с полным контрактом варианта и зависимостей; общие каталожные карточки можно кешировать отдельно. Правила существующего кеша — в [справочнике ключей](../liquid-widget-cache-keys/reference.md).

## Колонки и различия

Предпочтительный вариант для удаления и очистки — сохранить серверные ячейки и удалить колонки, которых больше нет в актуальном списке. Каждая ячейка, включая карточку и кнопку удаления, должна иметь ID своего товара. Подписи характеристик не удаляются вместе с первой товарной колонкой. На узком экране дай таблице горизонтальную прокрутку; число колонок CSS пересчитывается по оставшимся товарам.

`property.differ?` описывает исходное сравнение. После удаления одной колонки разные значения могут стать одинаковыми: пересчитай различия среди оставшихся, затем примени локальный переключатель. Не используй серверный класс `same-row` как постоянную истину.

Удобно хранить значения каждой ячейки отдельно от её оформления:

```liquid
{% capture cell_values %}[{% for characteristic in product.properties[property.handle].characteristics %}{{ characteristic.title | json }}{% unless forloop.last %},{% endunless %}{% endfor %}]{% endcapture %}
<td data-compare-product-id="{{ product.id }}"
    data-compare-values="{{ cell_values | escape }}">
  {% for characteristic in product.properties[property.handle].characteristics %}
    {{ characteristic.title | escape }}{% unless forloop.last %}, {% endunless %}
  {% else %}
    —
  {% endfor %}
</td>
```

Для сравнения разбирай JSON ячейки, а не `innerHTML` с изображениями/кнопками. Определи семантику многозначной характеристики: если порядок незначим, сравнивай нормализованные наборы, не порядок вывода. Отсутствие значения и декоративный прочерк не должны становиться разными характеристиками.

Если строишь строки заново из JS-данных, вычисляй **каждую ячейку по соответствующему product ID**. `push` только найденных свойств с последующим заполнением пропусков в конце сдвигает значения: при `[товар без размера, товар размера XL]` должно получиться `[—, XL]`, а не `[XL, —]`.

## Источник состояния и штатные действия

`Compare.remove({ item: id })` удаляет позицию, `Compare.clear()` очищает список. Альтернатива — штатные кнопки `data-compare-delete="ID"` и `data-compare-clear`. Выбирай один путь для действия: если оставляешь штатный data-атрибут, не добавляй свой второй вызов Compare на тот же click. Внутри формы такие кнопки имеют `type="button"`.

Событие `update_items:insales:compares` получает `data.products` — актуальный список, по которому можно сопоставить ID. `remove_item:insales:compares` также содержит `data.action.item`; после удаления приходит и update. Не уменьшай счётчик или число колонок дважды, обрабатывая оба события как независимые удаления. Полнота характеристик внутри `data.products` не гарантируется этим контрактом. `Compare.update()` асинхронен и не возвращает Promise с товарами.

Не требуется собственное хранилище сравнения. Два экземпляра получают один общий список, но состояние «только различия» принадлежит каждому экземпляру. После удаления последнего товара скрываются таблица и неприменимые действия, показывается редактируемое пустое состояние.

## Дозагрузка и жизненный цикл

Для удаления готовых колонок повторная загрузка товаров обычно не нужна. Если задача требует добавить колонку, которой нет в серверной разметке, отдельно реализуй подтверждённое получение и построение её данных; одного ID недостаточно для выдуманного названия/характеристик.

`Products.getList(ids)` возвращает jQuery Promise с map `{[id]: product}`, а не готовые строки таблицы. Не считай наличие `properties` доказательством вложенных характеристик: возможны нормализованные объекты и исходные `properties`/`characteristics`, связываемые по `property_id`. При таком рендере сначала нормализуй подтверждённую форму ответа.

Асинхронный ответ применяется только к тому снимку списка, для которого он запрошен: используй номер запроса/поколения и проверку disposed. Снимок B не должен быть перезаписан запоздавшим ответом A. Успешный resolve с пустым map не подтверждает полноту загрузки; не заменяй им непустую таблицу без обработки этого состояния.

Сохраняй callback EventBus и отписывайся тем же callback перед повторным mount. Перед удалением или заменой содержимого владелец явно вызывает `root.__comparePageCleanup`. `off/on` локальных кликов не снимает EventBus, а само удаление DOM не вызывает cleanup. Контракт владельца — в [runtime](runtime.md); не уничтожай общий Compare при удалении секции. Не пересоздавай глобальные подписки из callback обновления.

## Проверка

Проверь 0/1/несколько товаров, отсутствие характеристики у первого и среднего товара, пустые/многозначные значения, кавычки и `&`, ru/en и очищенные подписи. Контраст: `[красный, синий, синий]` → удалить красный → строка цвета одинакова. Переключатель одного экземпляра не меняет другой; удаление/очистка меняют оба.

Если есть дозагрузка, проверь ответы B→A, пустой результат и удаление секции до ответа. Повторный mount проверяй одним действием от клика; удаление — отсутствием оставшихся подписок. В браузере проверь доступ к последней колонке и кнопкам при390px. С доступной витриной отдельно подтверди реальное удаление/очистку и состояние после reload; DOM-фикстура этого не доказывает.
