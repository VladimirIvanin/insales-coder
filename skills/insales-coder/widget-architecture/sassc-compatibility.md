# Современный CSS в SassC/LibSass

SassC — Ruby-обёртка над LibSass. Ниже особенности LibSass3.6.4, используемого с SassC2.4.0. Для другой версии сверь результат целевой компиляции. Это практическая памятка, не полный список CSS-возможностей.

LibSass не обязан понимать каждое новое свойство: незнакомые значения и at-rules часто передаются в CSS. Основной риск — пересечение нового CSS-синтаксиса с Sass-парсером и встроенными Sass-функциями. Поэтому различай ошибку сборки, изменение результата и поддержку конечным браузером.

## Ошибки и обходы

| Конструкция | Что происходит | Как записать для LibSass |
|---|---|---|
| `min(100%, 390px)`, `max(1rem, 20px)` | Вычисляются как Sass-функции; несовместимые единицы вызывают ошибку | `unquote("min(100%, 390px)")`; для ограничения ширины также подходят `width:100%; max-width:390px` |
| `min(var(--width), 390px)` или `min(calc(...), ...)` | Sass ожидает число и отклоняет CSS-выражение | Экранируй весь внешний вызов через `unquote` |
| `rgb(10 20 30)`, `rgb(10 20 30 / 50%)` | Старый `rgb` ожидает отдельные аргументы | `rgba(10, 20, 30, .5)` либо `unquote("rgb(10 20 30 / 50%)")` |
| `hsl(120deg 50% 50% / .5)`, `hsl(var(--hsl))` | Конфликт со старой сигнатурой `hsl` | `hsla(120deg, 50%, 50%, .5)` либо `unquote` вокруг CSS-вызова |
| `rgb(from var(--base) r g b / .5)` | Относительный цвет попадает в старую Sass-функцию | `unquote("rgb(from var(--base) r g b / .5)")`; поддержку относительных цветов проверяет браузер |
| `filter: invert(var(--invert)) grayscale(var(--gray))` | Sass-функции ожидают цвет вместо значения CSS-фильтра | `filter: unquote("invert(var(--invert)) grayscale(var(--gray))")` |
| `round(up, 2.3px, 1px)`, `abs(var(--offset))` | Совпадение со встроенными числовыми функциями: неверное число аргументов/тип | Экранируй соответствующий CSS-вызов через `unquote` |
| `@media (width >= 768px)`, `@media (400px < width < 800px)` | Старый media-парсер не принимает range-синтаксис | Предпочтительно `@media (min-width:768px)`; для включённого диапазона — `min-width` вместе с `max-width` |
| `attr(data-width type(<length>), 10px)` | Парсер выражений отклоняет `<length>` | `unquote("attr(data-width type(<length>), 10px)")`; отдельно проверь поддержку типизированного attr в браузере |

Не заменяй строгий media-диапазон `width > X` на включённый `min-width:X`, если различие на границе существенно. Можно сохранить исходное условие интерполяцией:

```scss
@media #{unquote("(width > 768px)")} {
  .panel {
    display: grid;
  }
}
```

Обычные `min-width`/`max-width` проще, когда они выражают нужное условие. Успех range-условия внутри `@container` не означает поддержку такого же синтаксиса специальным парсером `@media`.

## Компилируется, но результат меняется

- `filter: opacity(var(--opacity))` может превратиться в `filter: alpha(var(--opacity))` без ошибки сборки. Для сохранения CSS-функции используй `unquote("opacity(var(--opacity))")`. Числовые `opacity(.5)`, `invert(.5)` и `grayscale(50%)` не требуют такого обхода в этой версии.
- `(16 / 9)` — Sass-деление, результатом будет число. Если нужен CSS-разделитель, пиши `aspect-ratio: 16 / 9` без Sass-скобок; арифметику браузера выражай через `calc()`.
- В custom properties `$variable` не подставляется автоматически: `$size:10px; --size:$size` оставляет `$size` в CSS. Правильно `--size: #{$size}`.

Проверяй не только exit code, но и итоговые значения CSS. Не оборачивай весь stylesheet в строку: обход нужен конкретному выражению.

## Что не следует запрещать автоматически

Следующие формы проходят через LibSass3.6.4 в CSS; это **не подтверждение их поддержки целевым браузером**:

| Формы | Поведение компилятора |
|---|---|
| `calc(100% - var(--gap))`, `clamp(1rem, 2vw, 2rem)` | Сохраняются как CSS-выражения |
| `oklch(65% .2 30)`, `color-mix(in oklab, red 30%, blue)`, `color(display-p3 1 0 0 / .5)` | Передаются как CSS-функции; не становятся вычисляемыми Sass-цветами |
| `#1234`, `#11223344` | Сохраняются; не объявляй альфа-hex неподдержанным только по возрасту LibSass |
| `mod(10px, 3px)`, `height:100dvh`, `width:30cqw`, `grid-template-columns:subgrid` | Не требуют вычисления LibSass |
| `:has(> img)`, `:is(.a, .b)` | Селекторы сохраняются |
| `@container`, `@layer`, `@starting-style` | Неизвестные at-rules могут передаваться дальше с вложенными правилами |

Sass-вложенность при этом разворачивается компилятором. Не считай её универсальным сохранением нативного CSS nesting. Для `@scope` и других правил со специальной областью действия проверяй итоговые селекторы: добавленная обёртка виджета также остаётся частью результата.

## At-rules внутри обёртки виджета

Отдельный риск — `@property`. Внутри селектора виджета LibSass может собрать такую структуру без ошибки:

```css
@property --example-progress {
  .widget-wrapper {
    syntax: "<number>";
    inherits: false;
    initial-value: 0;
  }
}
```

Дескрипторы оказались внутри селектора, а не непосредственно в `@property`. Чтобы сохранить регистрацию, выведи только её из обёртки:

```scss
@at-root {
  @property --example-progress {
    syntax: "<number>";
    inherits: false;
    initial-value: 0;
  }
}
```

Регистрация глобальная, поэтому имя свойства должно принадлежать виджету и не конфликтовать с другими компонентами. Не выноси через `@at-root` все обычные стили. У заявления порядка `@layer reset, theme;` также проверяй место в итоговом CSS: оно может остаться внутри селектора. Это отличается от блока `@layer components { … }`, который компилятор поднимает наружу.

## CSS и возможности языка Sass

`@use`, `@forward`, модули `sass:math`/`sass:color` и вызовы вроде `math.div()` — возможности современного **Sass**, а не CSS. LibSass их не реализует. Не переноси примеры Dart Sass в snippet.scss без адаптации.

В `unquote` Sass-переменные подставляются интерполяцией, CSS-переменные остаются выражением браузера:

```scss
$panel-max: 390px;

.panel {
  width: unquote("min(100%, #{$panel-max})");
  color: unquote("rgb(var(--rgb-channels) / .5)");
}
```

Здесь `--rgb-channels` должен содержать каналы через пробелы. Вариант `rgba(var(--rgb), .5)` тоже компилируется, но требует каналов через запятые; эти форматы нельзя смешивать.

Официальные пояснения: [вычисления и min/max](https://sass-lang.com/documentation/values/calculations/), [range media queries и CSS at-rules](https://sass-lang.com/documentation/at-rules/css/), [значения custom properties](https://sass-lang.com/documentation/breaking-changes/css-vars/), [статус LibSass](https://sass-lang.com/blog/libsass-is-end-of-life/). Совместимость конкретной формы определяют версия компилятора, полученный CSS и целевой браузер.
