# Страница товара с галереей

[Полный пакет](examples/product-detail/info.json): [Liquid](examples/product-detail/snippet.liquid), [JS](examples/product-detail/snippet.js), [SCSS](examples/product-detail/snippet.scss), [форма](examples/product-detail/settings_form.json), [defaults](examples/product-detail/settings_data.json), [сообщения](examples/product-detail/messages.json). Скопируй семь файлов и выбери собственный handle. Размещение — `content`, страница — `product`, категория — `products-cards`. Используются `jquery`, `commonjs_v2` и `my-layout` для `.layout__content`.

Пример подходит для обычных товаров с одним или несколькими вариантами. Он показывает каталоговые название, фотографии, описание, цену и наличие; подписи покупки и цвета редактируются. На desktop фотография и сведения расположены рядом, на mobile — последовательно. Без фотографий выводится текст, при одном фото нет ряда миниатюр. Пустые описание и старая цена не создают отдельные блоки.

## Данные и покупка

Цена, варианты и количество обслуживаются common.js через одну форму `data-product-id`, `data-product-json`, `data-product-variants`, `data-quantity` и `data-item-add`. Не добавляй рядом свой запрос изменения корзины. Начальная цена выводится Liquid; `data-product-card-price` и `data-product-card-old-price` обновляют её после выбора варианта. Нулевая цена получает редактируемую подпись; сама нулевая цена не вводит отдельного запрета покупки. Наличие сериализуется как JSON и затем экранируется для HTML целиком.

Форма содержит нативный селектор с настоящими ID. Common.js строит из него `option-select` для каждой характеристики. `aria-label` исходного селектора — fallback; после инициализации JS подписывает созданные selects названиями характеристик. Собственных ID, зависящих только от product.id, здесь нет, поэтому два экземпляра одного товара не создают коллизий разметки.

Покупка выводится при `account.show_cart?` и `product.show_cart_button`. Пример намеренно не собирает комплекты и аксессуары: для этих товаров остаются сведения и редактируемая подпись без кнопки покупки. Для их поддержки добавь соответствующие штатные элементы и проверь обязательные опции; одного `variant_id` недостаточно. Быстрая покупка, услуги и ссылки на маркетплейсы также требуют подходящего сценария вместо механического показа кнопки корзины.

Недоступный вариант блокирует покупку. Исключение соответствует режиму `settings.product_not_available == 'shown'`, когда `account.forbid_order_over_existing == false`: магазин разрешает заказ отсутствующего товара. Режим предзаказа требует отдельной штатной кнопки и модального сценария; пакет не выдаёт обычное добавление за предзаказ.

## Смена варианта и lifecycle

В проверяемом контракте common.js изменение характеристики ставит обновление в очередь, а `update_variant:insales:product` приходит после применения варианта и проверки количества. JS перехватывает начало выбора на форме и временно блокирует **только fieldset количества и покупки**. Выбор других характеристик остаётся доступным. Разблокирование происходит по событию именно этой формы; событие другого экземпляра и сохранённое событие другого товара не снимают блокировку. Фиксированного timeout и принудительного сброса на `1` нет. Штатная проверка минимального количества и остатков сохраняется. Не возвращай сохранённое сырое значение количества в `update_variant`: common.js уже мог уменьшить его под остаток нового варианта. Например, при смене с количества 3 на вариант с остатком 2 итоговое поле должно содержать 2, а не восстановленные 3.

`Products.getInstance($(form))` подготавливает экземпляр через Deferred. Если он уже существует и нового события нет, callback использует его каталоговые `product.variants` и текущее поле `variant_id` для начального наличия. Не используй DOM-атрибут `data-product-json` как постоянное хранилище: common.js может удалить его после чтения. При смене сборки сверь этот контракт, особенно порядок событий. Общие `before` и `always` не заменяют подтверждения смены варианта.

Галерея переключает только фотографию своего экземпляра и не подписывается на глобальную смену варианта; набор фотографий остаётся общим для товара. Именованный `off/on` не удваивает клики. Подписка готовности покупки снимается по той же ссылке callback перед повторным запуском и при удалении формы/замене содержимого. Если владелец уже предоставляет teardown, подключи этот cleanup к нему вместо второго наблюдателя. Не уничтожай общие Products/Cart при удалении одной секции.

## Адаптация и проверка

Сохраняй обязательные data-атрибуты при изменении оформления. Для варианта с фото, zoom или видео добавляй нужный компонент вместе с его зависимостью и cleanup. Для сравнения, избранного или опций используй [разметку common.js](../commonjs-widget/markup.md). Не подменяй данные каталога настройками экземпляра.

Офлайн проверь metadata, Liquid, JS и SCSS, в том числе подписи с кавычками и `&`, отсутствие фото, один вариант, нулевую цену, скрытую покупку и два одинаковых товара. DOM-harness может проверить блокировку до события, независимость экземпляров, повторный запуск и отписку; он не подтверждает цену или заказ на витрине.

С доступной темой проверь 390/1440 px и быстрый путь «выбрать вариант → сразу изменить количество → купить». Проверь variant_id, фактическое количество и сумму в корзине, переходы наличия и сохранение настроек. Если выбор ещё обрабатывается, количество и покупка должны быть временно недоступны; после готовности введённое количество сохраняется с учётом настоящего остатка. Проверь перерисовку в редакторе и удаление секции. Границы общей реализации описаны в [runtime](runtime.md).
