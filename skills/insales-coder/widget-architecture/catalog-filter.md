# Фильтр категории: AJAX-группы и диапазоны

Используй для фильтра с ценой, характеристиками, изображениями значений и мобильной панелью. Пакет gen4: страница `collection`, размещение `sidebar` или требуемое темой `content`, категория `filters`. Для AJAX-компонента нужны `commonjs_v2`, для jQuery-кода — `jquery`, для диапазонов — `nouislider`. Раскладку и блокировку прокрутки объявляй отдельными зависимостями, когда используешь их API.

Форма `method="get"`, `action="{{ collection.url }}"`, `data-ajax-filter`; группы рисует common.js, товары и их загрузку не дублируй. Шаблоны и данные — в [AJAX-компонентах](../commonjs-widget/ajax-components.md#ajax-фильтры), API слайдера — в [числовых фильтрах](../libraries/navigation-filters.md#nouislider--диапазон-числового-фильтра).

## Шаблоны и события

Внутри формы нужны контейнер `data-ajax-filter-items`, шаблоны группы, обычного значения, значения-изображения, цены, числовой характеристики и прелоадера. Для длинных групп добавь `data-ajax-filter-template-view-all-btns` с обеими кнопками `data-ajax-filter-view-all-btn` / `data-ajax-filter-hide-all-btn`: компонент ищет их при дозагрузке. Не ограничивай показ произвольными `nth-child`, скрывающими выбранные значения; используй состояния списка компонента. `expanded` ставится на **группу** `[data-ajax-filter-item]`, а `ajax-filter-short-list-item-visible` — на элементы короткого списка. Наличие кнопок само не скрывает значения. Например:

```scss
[data-ajax-filter-item]:not(.expanded) {
  [data-ajax-filter-item-content-list-item]:not(.ajax-filter-short-list-item-visible):not(.ajax-filter-item-checked) {
    display: none;
  }

  [data-ajax-filter-hide-all-btn] {
    display: none;
  }
}

[data-ajax-filter-item].expanded [data-ajax-filter-view-all-btn] {
  display: none;
}
```

Поддерживай `ajax-filter-item-checked` по фактическому checkbox.checked, в том числе после ручного выбора. Если нужны изображения значений, активируй их строковым `"useImages":"true"` или редактируемой настройкой; один template-color при постоянно выключенном useImages не обеспечивает эту функцию.

Поля, назначаемые компонентом:

| Критерий | Имя поля |
|---|---|
| Цена | `price_min`, `price_max` |
| Текстовая характеристика | `characteristics[]` |
| Значение параметра | `options[ID][]` |
| Числовая характеристика | `properties_gt[ID]`, `properties_lt[ID]` |
| Наличие | `only_available` |

Событие `init-filter:ui-ajax-filter` передаёт `{filterNode}`. Оно не означает, что все фильтры страницы принадлежат этому виджету: проверь, что узел — твоя форма или находится внутри неё, затем инициализируй только её диапазоны.

`filter-item-loaded:ui-ajax-filter` передаёт `{filterItem, checked, classList}` **после замены старой группы**. В своём узле восстанови выбранные checkbox по `input.value`, классы и состояние раскрытия, затем подготовь диапазоны/отображение списка. Сравнивай значения напрямую, не интерполируй строки с кавычками в CSS-селектор. Если родитель заменён, старые listeners/dataset-флаги не инициализируют новую форму.

События progress/error нельзя придумывать по аналогии с другими компонентами. Их наличие и формат проверяются отдельно; прелоадер и классы загрузки не подтверждают обработку отказа сети.

## Числа и noUiSlider

Источник границ — `data-range-min/max/start/end/step` на `[data-ajax-filter-range]`, внутри него находятся поля min/max и узел слайдера. Не применяй `Math.floor` к числовой характеристике: так теряются дробные значения и шаг. Различай пустую строку и ноль: `Number('') === 0`, а `value || fallback` заменяет настоящий 0. Используй проверку пустого значения и `Number.isFinite`.

Clamp значений выполняется к настоящим границам. При `min === max` диапазон не даёт выбора: покажи значение, отключи его критерии и не создавай активный слайдер с выдуманным максимумом `min + step`.

Синхронизируй поля из значений слайдера до отправки формы. Граница, равная общему минимуму/максимуму, не ограничивает выборку: её input можно отключить. Вводимое поле должно оставаться доступным для изменения, даже если пока отключено для GET: например, включай по клику/фокусу на его label. После blur нормализуй значение и передай его в slider.set. Учитывай, что программный `set`/`reset` может вызывать события библиотеки: это не обязательно отдельное действие человека.

Повторный init не должен создавать второй noUiSlider или второй blur-handler. Готовность привязывается к живому `slider.noUiSlider`: если destroy удалил экземпляр, старый dataset-флаг уже не подтверждает инициализацию. Удаляй свой флаг при teardown либо проверяй сам экземпляр; иначе сочетание «destroy всех → пропустить ready-узлы» оставит диапазоны без слайдеров. При замене диапазона уничтожь именно свой старый экземпляр и снимай обработчики по сохранённым ссылкам. Настоящая библиотека нужна для проверки событий и формата get(); заглушка не подтверждает её ограничения.

### Сброс — к полному диапазону, а не к start

`slider.reset()` возвращает **исходный start**, который может уже содержать активные ограничения. Это не сброс фильтра к полным границам.

При сбросе:

1. Временно подави автоприменение на время программных изменений.
2. Сними checkbox критериев и установи каждый слайдер в полные `[min, max]` из его данных.
3. После событий синхронизации отключи неограничивающие поля; для вырожденного диапазона отключены обе границы.
4. Отправь форму ровно один раз через выбранный путь submit.

Не очищай все hidden inputs и не используй безусловный `form.reset()`: они могут вернуть первоначально выбранные критерии или потерять контекст страницы. Сохраняй `order`, `page_size`, `lang`, `q`; их HTML-значения экранируются целиком. Контрольный случай: исходный диапазон0–10, активный2–8; после сброса в FormData нет `price_min`/`price_max`, но есть прежние order/page_size/lang/q. Так же проверь числовые характеристики.

## Мобильная панель и жизненный цикл

Стилизуй desktop-форму и мобильную панель по [Core CSS](core-css-reference.md). В `snippet.scss` селектор `body.some-lock` не меняет body: платформа добавит перед ним селектор обёртки виджета. Для scroll lock используй подходящий API с освобождением собственного lock; глобальный стиль срабатывает только если он действительно доставлен вне scope.

Открытая панель получает корректную модальность, фокус внутри, закрытие Escape и возврат фокуса к доступной кнопке. Backdrop не является focus target. Не ставь `aria-modal="true"` обычной desktop-форме. ID/aria-controls уникальны для экземпляра; не полагайся на недокументированную переменную Liquid для ID. Вариант с нативным dialog или подтверждённой библиотекой проверяй на целевых браузерах.

При resize в desktop, закрытии, удалении и замене формы освободи lock и внешние подписки. Общий класс body, который снимает любой экземпляр, может разблокировать чужую панель. Постоянный флаг `root.dataset.ready` не заменяет проверку текущей формы и cleanup: после замены HTML корень остаётся прежним. Механизмы удаления описаны в [runtime](runtime.md#внешние-ресурсы-и-teardown).

Пустая выдача с активными критериями не скрывает форму/сброс. Не создавай условие показа только `collection.products.size > 1`.

## Проверки

Проверь реальные шаблоны common.js и настоящую сборку noUiSlider: два экземпляра, чужой init, AJAX-замену группы с выбранным checkbox, повторный mount, ноль и дробный шаг, пустой/равный диапазон. Сброс с исходными активными start должен убрать ограничения. Проверь FormData с q, содержащим кавычки и `&`, и число отправок после checkbox, ручного ввода, движения ползунка и сброса.

На390px проверь панель действием: фокус, Tab/Escape, прокрутку, resize и удаление открытой формы. Офлайн-проверка не подтверждает серверную выдачу, человекочитаемые URL и результат применения на витрине; с доступной темой проверь их отдельно.
